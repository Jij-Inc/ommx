# Functionの表現と数値評価の契約

このReferenceは、[導入手順](../getting_started/install.md)のSDKを対象に、[Function Guide](../user_guide/function.md)から分離した表現・数値条件をまとめます。操作の引数・戻り値は {class}`~ommx.Function` のAPI Referenceも参照してください。wire表現は[対応するFunction Message](https://github.com/Jij-Inc/ommx/blob/python-3.0.0b7/proto/ommx/v1/function.proto)、評価の参照実装は[同リリースのRust実装](https://github.com/Jij-Inc/ommx/blob/python-3.0.0b7/rust/ommx/src/function/evaluate.rs)です。

## 多項式と複合式

Functionは定数・線形・二次・多項式、およびスカラー演算を組み合わせた複合式を保持します。多項式の加算・減算・乗算・符号反転は多項式として正規化されます。打ち消しや浮動小数点のアンダーフローで実際にゼロになった項は削除しますが、有限かつ非ゼロの係数を、評価時の`atol`で削除することはありません。

`Function`の除算は、除数が定数であっても複合式です。整数べきも、恒等演算や定数の畳み込みを除き、非負指数であっても自動的には展開されません。展開済み多項式が必要なら、例えば`g ** 2`ではなく`g * g`を使います。

複合式の`degree()`と`num_terms()`は`None`を返し、`terms`などの多項式用係数属性は`TypeError`になります。`almost_equal()`は多項式では係数を、複合式では式構造を比較し、任意の式の大域的な等価性を判定しません。

## 演算順序とwire表現

複合式は括弧と演算順序を保持します。オペランドを左から右へ評価し、加算や乗算も一つの適用ごとに二つの値を組み合わせます。例えば`(abs(a) + abs(b)) + abs(c)`と`abs(a) + (abs(b) + abs(c))`は、同じ演算順序へ自動的に並べ替えません。オーバーフローや未定義演算の発生は、この順序にも依存します。

Messageは複合式を、再帰的にネストしたtreeではなく、flatな逆ポーランド記法（RPN）の命令列として保存します。命令の種類とwireの構造は、上記Function Messageが定義します。Pythonで式を構築する際に、その命令列を直接作る必要はありません。

## 整数べきと未定義な入力

`fx ** n`と`fx.powi(n)`は同じ整数べきの操作です。指数は符号付き32 bit整数で、浮動小数や関数値の指数、`2 ** fx`のような反転累乗はサポートしません。

明示的な評価では、`atol`によって$|v|\leq\mathtt{atol}$（境界を含む）をゼロとみなします。`atol`を省略した場合は、その評価処理の既定値を使います。

| 演算 | 数値条件・結果 |
|---|---|
| `signum(v)` | $|v|\leq\mathtt{atol}$なら0、その区間より小さければ−1、大きければ1 |
| 除算 | 分母の絶対値が`atol`以下なら未定義 |
| 負の整数べき | 底の絶対値が`atol`以下なら未定義 |
| ゼロ乗 | `0 ** 0`も1 |
| 負の底 | 指数が整数なのでサポートする |

未定義の演算や非有限の中間結果は、Pythonでの点評価では`ValueError`になります。式に必要な変数IDが足りない場合も評価できません。

除算や負の整数べきを含む式は、すべての入力で値を持つとは限りません。定義域を消すような簡約は行わず、例えば`0 * (1 / fx)`も、$|\mathtt{fx}|\leq\mathtt{atol}$では未定義です。

## 部分評価と許容誤差

式の構築・代入・部分評価は、後で指定する`atol`を暗黙の既定値で先取りして確定しません。ゼロ判定に依存する`Signum`・`Div`・負の`Powi`は式に残り、後続の評価で指定した`atol`が結果や定義域を決めます。すべての変数を部分評価で置き換えた後も、これらが複合式として残る場合があります。

`Linear`・`Quadratic`・`Polynomial`の部分評価は元のPython型を保ちます。複合Functionでは、未代入の変数に依存する式構造を保ちます。閉じた部分式を定数に畳み込むのは、結果が`atol`に依存しない場合です。

{meth}`~ommx.Function.evaluate_bound`も、ゼロに依存する演算には指定した`atol`を使います。同じ式を点評価するときも同じ許容誤差を使ってください。得た区間は実際の値域を含む近似であり、依存する変数を含む項同士の関係をすべて利用するわけではないため、最も狭い区間とは限りません。区間の作成失敗・未定義演算の例外は、同メソッドのAPI Referenceを参照してください。

これらのFunctionの数値条件は、Instanceが候補の離散変数を丸めたり、変数の定義域・制約の成立を検査したりする規則とは別です。候補全体の検査には[Solutionの評価モデル](../user_guide/solution.md)を使います。
