# Share an Artifact through a registry

**Create an Artifact under its distribution name, authenticate, then call `push()`.** Unlike file transfer, this requires network access and permission to upload to the destination.

This example stores a small JSON note in GitHub Container Registry (`ghcr.io`) and retrieves it on the receiver's side. Problems and evaluated results can be added to the same Artifact. If a local file is sufficient, use the [file-exchange Tutorial](../tutorial/share_in_ommx_artifact.md). Experiment is not a prerequisite.

## Environment and permissions

- Python SDK `3.0.0b7` from steps 1–2 of [the installation instructions](../getting_started/install.md).
- A GitHub account or organization and repository where you may upload data.
- Docker CLI for login, and connectivity to `ghcr.io`.

Check visibility and permissions before uploading data. Follow [GitHub Container Registry's official instructions](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry#authenticating-to-the-container-registry) for authentication, token scopes and organization SSO. Do not put tokens in a Notebook or shared source code.

Log in from a terminal with the appropriate username.

```bash
docker login ghcr.io -u YOUR-GITHUB-USER
```

OMMX uses Docker's credential configuration. Explicit `OMMX_BASIC_AUTH_*` environment settings take precedence when present. A receiver may not need login if the registry permits anonymous public downloads.

## Create under the distribution name and push

Replace `my-team`, `my-project` and tag `trial-1` with a destination you can write. Running the placeholder unchanged does not give access to the OMMX project's registry. Choose a new tag that does not overwrite an existing distribution.

```python
from ommx.artifact import ArtifactDraft

draft = ArtifactDraft.for_github(
    org="my-team",
    repo="my-project",
    name="candidate-notes",
    tag="trial-1",
)
_ = draft.add_json({"trial": 1, "note": "shared record"}, title="summary")
artifact = draft.commit()
print(artifact.image_name)
artifact.push()
```

The name is `ghcr.io/my-team/my-project/candidate-notes:trial-1`. Committing stores it locally; only `push()` sends it remotely. Add `draft.add_instance(instance)` or `draft.add_solution(solution)` before committing if you also have problems or evaluations to distribute.

{meth}`~ommx.artifact.ArtifactDraft.for_github` also sets source-repository metadata, but does not create repositories or grant permissions. Names generated by local `new_anonymous()` are not remote distribution destinations.

## Retrieve and read on the receiver's side

Run this on another machine, or in a process using a Local Registry without this reference. Private data also requires the receiver's read permission and login.

```python
from ommx.artifact import Artifact

artifact = Artifact.load(
    "ghcr.io/my-team/my-project/candidate-notes:trial-1"
)
layer = next(
    layer
    for layer in artifact.layers
    if layer.annotations.get("org.ommx.user.title") == "summary"
)
summary = artifact.get_json(layer)
assert summary == {"trial": 1, "note": "shared record"}
```

`load()` prefers the local reference, fetching remotely and storing locally only when absent. It does not refresh an updated tag on every call. To share or record exact content, use a reference such as `ghcr.io/.../candidate-notes@sha256:...` with the publisher's verified manifest digest. See [Artifact storage and identity](../user_guide/artifact.md) for names, tags and digests.

## If retrieval fails

Check the complete reference, separate read/write permissions, login hostname and network connectivity. A local commit alone does not distribute data: the sender's push must have succeeded.

See {meth}`~ommx.artifact.Artifact.load` for authentication, access-denial, missing-reference and communication exceptions. You do not need to delete existing data merely to rename or manage references. See [Manage the Local Registry](./manage_local_registry.md).
